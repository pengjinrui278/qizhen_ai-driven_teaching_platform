# 学镜 · 参赛演示与视频拍摄指南

> 面向：第二届全国高校"启真问智"教育教学人工智能大赛 · 现场决赛
> 用途：① PPT 该放什么、每页讲什么；② 演示视频怎么拍、拍前准备什么
> 编写日期：2026-10-15　核对基准：当前 `work/scissors` 分支实机状态

---

## 0. 先读这一节：三件事决定成败

**第一，评委的评分维度是这五个**（`docs/competition/通知原文.md` 原话）：

> 「大赛将从**创新性、教学应用价值、技术实施质量和用户体验与可推广性**等维度对作品进行综合评价。特别关注作品在实际教学场景中的**落地效果**及**"师-生-机"协同**的体现程度。」

所以 PPT 和视频的重点不是"功能多"，而是**"师-生-机协同"这条线有没有走通**。评委最想看到的画面是：学生的求助 → 变成证据 → TA 确认 → 教师改了教学 → 学生下一次被帮得更好。**这条闭环必须在一段连续的画面里出现**，散着讲功能会丢分。

**第二，开发路线里有一条硬性展示要求**（`docs/development-roadmap.md` 开篇）：

> 「最终展示必须同时包含：1）Student Mirror；2）五门 Course Mirror；3）Assignment Workspace；4）学生端、课程建设端、教师/TA 端三个完整角色界面；5）数据来源、Harness、Eval、隐私和生命周期治理。」

**五门课 + 三端，一个都不能少。** 视频里哪怕每门课只给 5 秒，也必须出现。

**第三，这个项目最值钱的东西不是功能，是"克制"。** 别人做的是"更会做题的 AI"，学镜做的是"不替你做题、但记得你怎么卡住的 AI"。所有的技术设计（提示阶梯只给一级、反馈页不做能力评分、教师看不到私人对话、材料不够就如实说）都是这一条的体现。**这一条要在 PPT 里至少占两页，视频里至少给一个特写。**

## 一、作品定位：PPT 开场的三页

### 第 1 页 · 封面

- 标题：**学镜 Learning Mirror**
- 副标题：**面向大学数理课程的个性化学习智能体**
- 一句话：**不是"更会做题的 AI"，而是一套越用越懂你的教学智能体系统**
- 底部：浙江大学 · 团队名 · 赛道（**教育教学智能体**赛道）

### 第 2 页 · 问题（这一页决定评委要不要认真听）

核心论点：**真正没有被看见的，是"学生得到最终答案之前发生了什么"。**

把传统的作业链画出来，然后在最后一步画一个大叉：

```
纸上做题 → 卡住 → 查教材 / 看部分解答 / 问 AI / 看视频 / 直接看答案
        → 理解或模仿后重新组织答案 → 拍照上传 → 助教看到【最终成品】并给分
                                                    ↑
                                        过程信息在这一刻基本已经消失
```

然后抛出这些问题（原话，直接用）：

> 「学生最初有没有思路？」「是否知道该调用哪个定理？」「是否在产生关键中间对象时卡住？」「需要几级提示？」「是不是看完整答案以后才写出来？」「这次困难是不是过去已经出现过？」「是不是'看答案觉得会了'，但下一次仍然无法独立完成？」

**收尾一句**：「我们要采集的最重要的数据，是**学生从'不会'到'会'、从'卡住'到'继续'的过程中发生了什么**。」

### 第 3 页 · 定位与三个对象

放那张三端对照表（这张表是全场最好用的一页，建议在视频里也复现）：

| 对象 | 一句话职责 | 生命周期 |
|---|---|---|
| **Student Mirror** | 保存"**这个学生和知识之间是什么关系**" | 随学生 |
| **Course Mirror** | 保存"**这门课是什么、这道题怎么理解和处理**" | 跨届积累 |
| **Assignment Workspace** | 保存"**一个班一个教学阶段的临时上下文**" | 用完即退出 |

配一句原文：

> 「**Course Mirror 越用越懂课；Student Mirror 越用越懂人；Workspace 用完即退出。**」

**必须主动交代技术路线**（这一句能挡掉"你们是不是只是套了个壳"的质疑）：

> 「我们**不训练大模型**。用国内通用大模型当大脑 + 自建课程语料当资料（RAG 检索，**查资料不是训练**）+ 智能体代码当工作流程 + 评测题当质检。教材数据的授权范围本来就只开了'检索'，训练权限是关闭的，正好与这条路一致。」

> ⚠️ **口径提醒**：不要说"我们训练了模型""我们微调了五门课"。产品文档里明确写着「是否微调应由 Eval 结果决定，而不是为了'看起来训练过模型'而训练」。

## 二、PPT 分页要点

建议 24–28 页。下面按"必须讲"和"加分项"标注。

### A. 为什么要做（3 页）

| 页 | 要点 |
|---|---|
| A1 问题 | 见上面第 2 页 ✅必须 |
| A2 三个对象 | 见上面第 3 页 ✅必须 |
| A3 我们要证明的六个命题 | 用原文六条，PPT 上只留加粗部分 ✅必须 |

> 命题 1 学生愿意用一个"不会立刻把答案塞给你、但又不烦人"的数学 AI
> 命题 2 自然求助过程确实包含最终作业无法看到的学习证据
> 命题 3 跨多次交互后，这些证据能形成**可解释、可修正**的学习观察
> 命题 4 过程证据 + 全班作业 + TA 判断 → 教师能得到比"哪道题错得多"更有价值的教学信息
> 命题 5 同一个 Student Mirror 用统一协议调用五门 Course Mirror
> 命题 6 五门 Course Mirror 知识层/Harness 各不相同，但输出**统一格式的 Learning Evidence**

### B. 学生端（8 页）✅必须

| 页 | 讲什么 | 演示时指哪 |
|---|---|---|
| B1 学习首页 | 统一入口：课表、我的课程、进行中作业、最近学习；头像 | 首页一屏 |
| B2 课程学习 · 渐进提示 | **三级提示梯度**：我卡住了 → 再深入一点 → 梳理解题框架。**默认只给第一级** | 回答下方三个按钮 + 「提示 1/3」标签 |
| B3 课程学习 · 可核对 | 每条回答都带「资料来源」（教材页码 locator），回答前有「正在核对回答…」状态 | 展开「资料来源」 |
| B4 摘录与并排追问 | 框选回答片段 → 拼接成**并排子页面** → 就这些片段继续追问 → 子页面里还能再剪（嵌套） | 剪一刀、拼一个子页面 |
| B5 输入方式 | 公式所见即所得编辑（MathLive + 12 组学科符号面板）、拍照识题、拖入文档（PDF/Word/PPT/代码）、右侧 1/3 拖入=并排参阅不参与提问 | 公式面板 + 拖一个 PDF |
| B6 我的笔记 | Obsidian 式目录树（科目/时间两种整理）、★、备注、回收站 30 天、导出 **Word/PPT/HTML/Markdown**、附件多格式 | 笔记树 + 导出下拉 |
| B7 笔记模式（**这页是全片最亮的**） | 勾选回答 → 「存为笔记」→ agent **整理成一份**（去重、按主题重组、不照抄）→ **自动落库 + 可撤回**；页边偏好面板（结构/格式/图表/驱动/深浅/用途）往输入框插高亮要求；按教材章生成；`@` 引用笔记；**agent 直接管理笔记库**（改标题/移动目录/标星/删/还原） | 全套走一遍 |
| B8 学习反馈（学迹） | 最近进展（**只讲证据变化**）、学习时间线、科目占比、活动趋势、笔记产出；每张图配数据表；**明写"不是能力评分"**；观察可以**当场纠正** | 反馈页 + 点一次「纠正记录」 |

**B7 值得单独讲透的三点**（评委最容易在这里亮眼）：

1. **自动存但可撤回** —— 系统代你落库，事后给你一条「已存到 … › 《标题》」+ 撤回按钮。
2. **agent 能直接操作你的笔记库** —— 学生说「把散在科目根的笔记整理到第3章」，agent 就真的做了，并在回答里逐条回报「完成 N 项，M 项没做成」。
3. **它不许乱来** —— 只能动本人的笔记；模型编造的 ID 会被丢掉并**如实回报**；agent **没有"彻底删除"这个能力**，只能移进回收站。

**B8 的讲法**（这一页对抗的是"你们是不是在给学生打分"）：

> 「这一页里没有一个数字叫'掌握度'。我们只展示**证据和观察的变化**：哪条判断出现了相反证据、哪条观察被更正了。活动量（多少轮对话、多少份笔记）单独标注，并写明**活动量不代表掌握程度**。学生本人可以**当场纠正任何一条观察**。」

### C. 课程建设端（2 页）✅必须

| 页 | 讲什么 |
|---|---|
| C1 课程建设台 | 打开题目 → 结构化编辑（正文、关联知识点、**多种参考解法**、**教学要点 hint_ladder**、常见错误）→ 填审校说明 → **教师确认发布新版本**；TA 账号此按钮**禁用**（现场演示权限差异） |
| C2 版本与回滚 | 「贡献候选与版本记录」：待审核/待编辑/已发布/未采纳；eligible 候选可「打开编辑草稿」并自动挂上 **rights 四项开关**（runtime/rag/eval/training）；已发布的可「创建回滚版本」（需填回滚理由） |

**C2 要强调**：这是"**课程资产是可被审校、可被回滚的**"，不是聊天记录攒出来的。

### D. 教师 / TA 端（4 页）✅必须

| 页 | 讲什么 |
|---|---|
| D1 教学总览 | 进行中作业 / 已提交 / 待批改 三个数字 + 待批改列表 |
| D2 作业管理 | 布置作业（课程/班级/人数/要求/**资料保留时长**/确认到期清理）；作业码；加助教；结束作业；**删除作业资料（汇总报告保留）** |
| D3 作品批改 + **两级决策** | 「辅助批改」生成候选建议 → **TA 先确认/忽略** → **教师再「纳入报告」**。**这是"师-生-机"最直接的画面** |
| D4 教学报告 | 学习参与 / 作品提交 / 独立表现 / 确认问题 四个指标 + 已确认问题 + 教学建议 + 导出报告 |

**D3、D4 的讲法**（这段是拿分点）：

> 「AI 只负责**发现候选问题、聚合模式、减少机械工作**；数学判断权始终在 TA 和教师手里。教师端输出的不是'AI 批改了多少份'，而是'**本周值得教学关注的现象**'。」

### E. 五门课与学科 Harness（2 页）✅必须

这是**技术实施质量**维度最硬的一页。把实际注册的 harness 打出来：

| 课程 | 学科 Harness（代码里真实注册的） |
|---|---|
| **数学分析**（旗舰·深做） | 定理条件 `theorem_conditions` · 量词边界 `quantifier_boundary` · 证明逻辑 `proof_logic` · 提示泄露 `answer_leakage` |
| **常微分方程** | 符号残差 `symbolic_residual` · 初边值条件 `initial_boundary_conditions` · 存在唯一性 `existence_uniqueness` · 数值交叉核对 `numerical_crosscheck` |
| **大学物理** | 单位量纲 `unit_dimension` · 模型假设 `model_assumptions` · 方向与符号 `direction_sign` · 数量级 `magnitude_check` |
| **点集拓扑** | 定义与约定 `definition_convention` · 量词逻辑 `quantifier_logic` · 反例核对 `counterexample_check` · 条件替换 `condition_substitution` |
| **高等代数与解析几何** | 符号矩阵核对 `symbolic_matrix_check` · 秩与维数条件 `rank_dimension_conditions` · 充要性 `necessity_sufficiency` |

配一句原文解释 Harness 是干嘛的（**注意措辞，别说"保证 100% 正确"**）：

> 「Harness 的目标是**让 Course Mirror 更容易发现自己没有足够依据**，并在必要时重试、降级回答或明确表达不确定性。」

每门课还有**独立的课程教学策略**，例如：
- 数分：「明确量词顺序与变量依赖；使用定理前核对全部条件；证明必须区分直观与论证。」
- 大物：「先说明物理模型和假设，再检查单位、方向与极限情形；**不把数学运算代替物理解释**。」
- 心理学：「不从聊天做临床诊断或人格贴标签。」

**这一页的潜台词**：证明"换一门课不是换一个 prompt"。

### F. 数据权利与隐私（3 页）✅必须

| 页 | 要点 |
|---|---|
| F1 六个授权字段 | 每个数据源**分别**声明 `allowed_for_runtime` / `allowed_for_rag` / `allowed_for_eval` / `allowed_for_training` / `retention_policy` / `license_note`。**检索与运行时双门控，代码里逐块过滤** |
| F2 三条不能越的线 | ① 私人对话与笔记**默认本人可见**，不因关联课程就向教师公开；② **不把"求助多"解释为"能力差"**，不把"看答案"作为惩罚性指标；③ 教师端**不做**"谁问 AI 最多"这类监控面板 |
| F3 生命周期 | 学生模型随学生生命周期结束而删除；班级临时上下文随作业周期清理；**只有去身份化、聚合、人工审核过的经验**才进课程长期资产 |

**F1 的金句**（原话，建议念出来）：

> 「'学生上传用于当前答疑'**不自动等于**'允许训练'；'购买教材'**不自动等于**'允许批量复制或模型训练'。」

**F2 的金句**：

> 「**信任一旦破坏，最珍贵的数据就会变成表演数据。**」

### G. 工程质量（2 页）✅强烈建议

评委里一定有懂工程的人，这两页专门给他们。

| 页 | 要点 |
|---|---|
| G1 测试与验收 | **后端 409 项自动化测试通过**；**22 个浏览器端到端验收脚本**（覆盖对话、摘录、笔记、反馈、教材库、课表、首页登录等）；每次改动跑全量回归 |
| G2 诚实边界（**这一页非常加分**） | 下面这些是"我们做不到、所以如实说出来"的地方 |

**G2 具体列这几条**（都是代码里真实存在的行为）：

- 一整章教材（300+ 块 / 5–14 万字符）**塞不进模型上下文**。做法是：**完整章节目录必发 + 按预算节选正文 + 如实写出"本章还有 N 块未列出"**，并要求模型在材料没覆盖的地方标注「（超出所给材料，待核对）」。
- 导出的 Word/PPT 是**单向导出**，不保证与网页逐像素一致；公式导出为纯文本。
- 扫描件抽不出文字时**直接说读不到**，不假装读过。
- 上传的文档超出额度时，回答里会说明"只看到文件名"。
- 「学镜**不替你做作业**」：习题只给思路与框架，不代写整份。

### H. 收尾（1 页）

十条共同原则，PPT 上只留这四条（最有辨识度的）：

1. **先帮助学生，再观察学生。**
2. **诊断是学习的副产品，不是额外负担。**（全程不用填任何问卷）
3. **一次行为不能定义一个学生。**
4. **个性化必须真正改变下一次帮助，而不只是改变展示文案。**

## 三、演示视频分镜脚本（约 7 分钟）

### 叙事骨架：跟着产品文档里那个"最终场景"走

产品文档写的验收画面就是最好的剧本（原话）：

> 「周三晚上，学生小王做数分作业，在一道 ε-δ 证明上卡住。他拍题、自己先想，然后点'我卡住了'。系统结合他的历史（曾在构造辅助对象时卡住过两次）只给第一级提示，而不是答案。他做出来后，系统记下一条学习证据——**全程不用填任何问卷**。
> 同一时间，TA 收到 AI 的批改辅助……教师据此决定下周一花十分钟讲这个问题。
> **学生的私人对话内容，教师全程看不到。**」

**视频就按这个时间线走，一条龙演下来。**

### 分镜表

| # | 时间 | 画面 | 操作步骤 | 旁白要点 |
|---|---|---|---|---|
| 0 | 0:00–0:20 | 黑底白字 | — | 「学生得到最终答案之前，发生了什么？」「传统作业链里，这些信息在提交那一刻就消失了。」 |
| 1 | 0:20–0:45 | 学习首页 | 展示首页一屏 | 「学镜：面向大学数理课程的个性化学习智能体。五门课、三个角色界面。先看学生端。」 |
| 2 | 0:45–1:35 | 课程学习 | 选数分 → 拍一道 ε-δ 题 → 识别成文字 → 先自己写两行 | 「他先自己试。卡住了，点『我卡住了』。」 |
| 3 | 1:35–2:20 | **一级提示（重点）** | 观察状态文案「寻知·正在查找教材 → 答疑·正在思考 → 正在核对回答」→ 只出现「提示 1/3」 | 「注意三件事：状态是分段的、提示**只给一级不是答案**、回答带『资料来源』可以核对到教材页码。」 |
| 4 | 2:20–3:00 | 追问与检查 | 点「再深入一点」→ 再点「梳理解题框架」 | 「三级提示梯度。他做出来了——**这条过程被记下来了**。」 |
| 5 | 3:00–3:40 | 摘录 + 并排子页面 | 框选两段回答 → 拼接成子页面 → 在子页面里继续问 | 「把关键片段剪下来、并排追问。所有结论都能回到原句。」 |
| 6 | 3:40–4:40 | **笔记闭环（全片最亮）** | 开「笔记」→ 勾选 3 处回答 → 存为笔记 → agent 整理 → **提示条「已存到…」+ 撤回** → 打开页边偏好面板点两个选项（看高亮块插进输入框）→ 说一句「把散在科目根的笔记整理到第8章」→ **操作回执** | 「学生要的笔记由他自己勾选，agent 负责整理成一份。存完给撤回。**agent 还能直接管理他的笔记库**——看这条回执，做了什么、哪项没做成都写清楚。」 |

## 四、拍摄前必须做的准备（**这一节最容易翻车，逐条做完再开机**）

### 4.1 ⚠️ 两个必须先解决的数据缺口

**缺口一：本地库里没有任何教师/TA 账号，也注册不了。**

实测：`data/browser-test.sqlite` 里 **35 个账号全是 `student`**，而 `.env` 里 `MIRROR_STAFF_INVITE_CODE=` 是**空的**——教师/TA 注册需要邀请码，空值直接 403。

**解决**：演示前在 `.env` 里补一行（值自定），然后**重启 API**：

```bash
MIRROR_STAFF_INVITE_CODE=demo-team-invite
```

再用这个邀请码注册一个教师账号（注册页选"教师"角色）。

**缺口二：作业空间、作品提交、课程修订全是 0 条。**

实测：`sandbox_policies = 0`、`assignment_submissions = 0`、`course_revisions = 0`。

**也就是教师端、课程建设端目前是空页面，现在开机拍出来全是空态。**

**解决**：按这个顺序预置一遍（大约 15 分钟）：

1. 教师账号登录 → **作业管理** → 布置作业（课程=数学分析，名称=「数列极限 · 第一次习题」，班级人数=32，记下**作业码**）
2. 换学生账号（用你已有的 `milkdragon`）→ **我的作业** → 输入作业码加入 → **提交作业**（作答内容填一段真实的 ε-δ 作答，勾选"提交给教师"）
3. 想演示"多人共性"的话，**再注册 2–3 个学生账号各提交一份**（批改页的学生列表才有内容）
4. 教师端 → **作品批改** → 点「辅助批改」→ 保存一次批改 → 点「汇总问题」
5. 教师端 → **课程建设** → 打开一道已有题目 → 改一处 → 填审校说明 → 发布一次（这样"版本记录"里才有东西）

> **验收标准**：教师端三个页面（总览/批改/报告）打开都不是空态；课程建设端「贡献候选与版本记录」至少有一条记录。

### 4.2 学生端数据也要喂一遍

现有演示账号只有 **7 段对话、2 篇笔记**，反馈页的图表会很空。

至少要补：
- **8–12 篇笔记**，分布在 2–3 个科目、不同目录，其中 2–3 篇标 ★
- **至少 3 个科目的对话**（这样"各科目学习占比"才有分段）
- **几条学习观察**：在对话末尾的「补充学习反馈」里点几次「仍有困难 / 这次独立完成」
- 想演示"观察被更正"的话，在反馈页对一条观察点一次「纠正记录」

### 4.3 环境准备

| 项 | 做法 |
|---|---|
| 起后端 | 仓库根目录：`apps/api/.venv/Scripts/python.exe -m uvicorn mirror_api.main:app --app-dir apps/api/src --port 8015` |
| 起前端 | `cd apps/web && node node_modules/next/dist/bin/next build`，然后仓库根 `node scripts/serve-static.cjs 3011` |
| **为什么用静态服务不用 dev** | dev server 编译 mermaid 极慢（10 分钟不完成），`serve-static` 秒开且把 `/api` 同源反代到后端 |
| 浏览器 | Edge/Chrome，**缩放 100%**，窗口 1600×1000 以上；`F11` 全屏；**隐藏书签栏**（Ctrl+Shift+B） |
| 关掉干扰 | 浏览器通知、系统通知、微信/QQ、输入法候选窗；**关掉 Windows 缩放动画** |
| 录屏 | OBS Studio（免费）：1920×1080、60fps、编码器选硬件（NVENC/QSV）；或 Win+G 自带录屏（简单但码率低） |
| 麦克风 | 用耳麦，别用笔记本内置麦；录之前试录 10 秒回放 |

### 4.4 ⚠️ 关于真实模型调用（务必知情）

`.env` 里是**真实 DeepSeek 接口**（`MIRROR_LLM_PROVIDER=openai_compatible`，模型 `deepseek-flash`，超时 300 秒，单次最大 32768 tokens）。这意味着：

- **每次提问都在花钱**，走一遍全脚本大约几十次调用。建议先规划好路径，别即兴乱点。
- **回答有延迟（几秒到几十秒）且内容不确定**。所以：
  - **关键镜头（#3 一级提示、#6 笔记整理、#10 辅助批改）不要直播等**，提前跑出来、确认内容合适了再拍。
  - 拍的时候**在等待期间切镜头或做旁白**，不要拍 20 秒的转圈。
  - **同一句提问多跑几次**，挑一个回答质量最好的版本用。
- **不要用 `MIRROR_LLM_PROVIDER=stub` 拍**。stub 是离线占位回答，内容很假，一眼看出来。

### 4.5 脚本与彩排

1. **先把旁白写成逐字稿**（按上面分镜表的旁白栏扩写），念一遍掐时长。
2. **按稿走两遍完整彩排**，只录屏不配音，检查：每步点击是否顺利、有没有空态、等待是否过长。
3. 记录**每个镜头的实际耗时**，据此调整旁白长度（宁可旁白短一点，画面多停两秒）。
4. **最后一遍正式录**，分镜分段录（OBS 支持按场景分文件），后期拼——不要一遍到底，错一个字全废。

## 五、绝不能说错的话（答辩防线）

| 别这么说 | 这么说 |
|---|---|
| 「我们训练/微调了大模型」 | 「我们不训练大模型：通用基座 + 自建课程语料检索 + 智能体工作流 + 评测题质检。教材授权的训练权限本来就是关闭的。」 |
| 「AI 能保证答案正确」 | 「Harness 让 Course Mirror **更容易发现自己没有足够依据**，必要时降级或明确表达不确定性。我们不宣称 100% 正确。」 |
| 「系统会给学生做能力评估」 | 「我们**不做能力评分**。只记录证据和观察，而且允许学生质疑和纠正。」 |
| 「老师在后台能看到学生的全部 AI 对话」 | 「**默认不把完整私人对话暴露给教师。**教师端看的是摘要、趋势和与教学相关的证据——这是设计上的边界，不是功能缺失。」 |
| 「求助多的学生能力差」 | 「**求助行为本身不是负面行为。**我们不把'求助多'解释为'能力差'。」 |
| 「五门课都已经产品化完成」 | 「**1 门深做（数学分析全闭环）+ 4 门真实可用**，用来证明架构可以从一门课扩展到多门课。」 |
| 「拾记/学迹是我们训练的五个模型」 | 「这是课程内的**五个逻辑角色**（答疑/寻知/编题/拾记/学迹），**各有工具和权限边界，不必各自微调一个模型**。」 |
| 「已经完成了真实课堂验证」 | 目前**没有**真实课堂/真实学生实验的数据。不要宣称已完成教学效果验证。（`docs/progress` 里的验收表明确写着"真机/教学质量 ⚠️ 未完成"） |

**评委可能追问的三个问题，准备这三句**：

1. **"这和直接问 ChatGPT 有什么区别？"**
   →「ChatGPT 给你答案；学镜**记得你怎么卡住的**，并且下一次给的帮助不一样。而且我们的回答可以核对到教材页码，材料不够时会如实标注。」

2. **"你们的 RAG 会不会泄露教材版权？"**
   →「教材数据的授权字段是**逐条**声明的，检索和运行时**双门控**，代码里逐块过滤。训练权限全部关闭，仓库和提交材料里不含教材原文。」

3. **"教师端会不会变成监控工具？"**
   →「不会，而且我们在产品文档里把它写成了负面清单：不做'谁问 AI 最多''谁疑似偷懒'这类面板。教师拿到的是'本周值得教学关注的现象'。」
