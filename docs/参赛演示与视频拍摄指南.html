学镜演示手册

PPT 该放什么、每页讲哪句；7 分钟演示视频的 13 个镜头怎么拍；开机前必须补上的两个数据缺口。

0先读这一节：三件事决定成败

第一 · 评分维度

重点是"师-生-机协同"，不是功能多

大赛从创新性、教学应用价值、技术实施质量、用户体验与可推广性四个维度评价，并"特别关注落地效果及"师-生-机"协同的体现程度"。

评委最想看到的画面是一条连续的闭环：学生的求助 → 变成证据 → TA 确认 → 教师改了教学 → 学生下一次被帮得更好。散着讲功能会丢分。

第二 · 硬性要求

五门课 + 三端，一个都不能少

开发路线开篇写明：最终展示必须同时包含 Student Mirror、五门 Course Mirror、Assignment Workspace、三个完整角色界面，以及数据来源、Harness、Eval、隐私与生命周期治理。

视频里哪怕每门课只给 5 秒，也必须出现。数分要证明闭环真的成立，其余四门要证明架构能扩展。

第三 · 真正的差异

最值钱的不是功能，是"克制"

别人做的是"更会做题的 AI"；学镜做的是不替你做题、但记得你怎么卡住的 AI。

提示阶梯只给一级、反馈页不做能力评分、教师看不到私人对话、材料不够就如实说——都是这一条的体现。

PPT 里至少占两页，视频里至少给一个特写。

1作品定位：PPT 开场三页

第 1 页

封面

  • 标题：学镜 Learning Mirror
  • 副标题：面向大学数理课程的个性化学习智能体
  • 一句话：不是"更会做题的 AI"，而是一套越用越懂你的教学智能体系统
  • 底部：浙江大学 · 团队名 · 赛道（教育教学智能体赛道）
第 2 页

问题：这一页决定评委要不要认真听

核心论点：真正没有被看见的，是"学生得到最终答案之前发生了什么"。

纸上做题 → 卡住 → 查教材 / 看部分解答 / 问 AI / 看视频 / 直接看答案
        → 理解或模仿后重新组织答案 → 拍照上传 → 助教看到【最终成品】并给分
                                                    ↑
                                        过程信息在这一刻基本已经消失

然后把这串问题抛出去（原话，直接用）：

「学生最初有没有思路？」「是否知道该调用哪个定理？」「是否在产生关键中间对象时卡住？」「需要几级提示？」「是不是看完整答案以后才写出来？」「这次困难是不是过去已经出现过？」「是不是'看答案觉得会了'，但下一次仍然无法独立完成？」

收尾一句：「我们要采集的最重要的数据，是学生从'不会'到'会'、从'卡住'到'继续'的过程中发生了什么。」

第 3 页

三个对象

这张三端对照表是全场最好用的一页，建议在视频里也复现。

对象一句话职责生命周期
Student Mirror保存"这个学生和知识之间是什么关系"随学生
Course Mirror保存"这门课是什么、这道题怎么理解和处理"跨届积累
Assignment Workspace保存"一个班一个教学阶段的临时上下文"用完即退出

「Course Mirror 越用越懂课；Student Mirror 越用越懂人；Workspace 用完即退出。」

然后主动交代技术路线——这一句能挡掉"你们是不是只是套了个壳"：

「我们不训练大模型。用国内通用大模型当大脑 + 自建课程语料当资料（RAG 检索，查资料不是训练）+ 智能体代码当工作流程 + 评测题当质检。教材数据的授权范围本来就只开了'检索'，训练权限是关闭的，正好与这条路一致。」

口径不要说"我们训练了模型""我们微调了五门课"。产品文档里明确写着「是否微调应由 Eval 结果决定，而不是为了'看起来训练过模型'而训练」。

2PPT 分页要点

建议 24–28 页。必须 是建议保留的硬内容，加分 视时间取舍。

A · 为什么要做

必须 · 3 页
页要点
A1 问题见第 1 节第 2 页
A2 三个对象见第 1 节第 3 页
A3 六个命题命题 1 学生愿意用一个"不会立刻把答案塞给你、但又不烦人"的数学 AI；2 自然求助过程确实包含最终作业无法看到的学习证据；3 跨多次交互后这些证据能形成可解释、可修正的学习观察；4 过程证据 + 全班作业 + TA 判断 → 教师能得到比"哪道题错得多"更有价值的教学信息；5 同一个 Student Mirror 用统一协议调用五门 Course Mirror；6 五门课知识层/Harness 各不相同，但输出统一格式的 Learning Evidence

B · 学生端

必须 · 8 页
页讲什么演示时指哪
B1 学习首页统一入口：课表、我的课程、进行中作业、最近学习、头像首页一屏
B2 渐进提示三级提示梯度：我卡住了 → 再深入一点 → 梳理解题框架。默认只给第一级回答下方三个按钮 +「提示 1/3」标签
B3 可核对每条回答都带「资料来源」（教材页码 locator）；回答前有「正在核对回答…」状态展开「资料来源」
B4 摘录追问框选片段 → 拼接成并排子页面 → 就这些片段继续追问 → 子页面里还能再剪（嵌套）剪一刀、拼一个子页面
B5 输入方式公式所见即所得编辑（MathLive + 12 组学科符号面板）、拍照识题、拖入文档（PDF/Word/PPT/代码）、右侧 1/3 拖入 = 并排参阅不参与提问公式面板 + 拖一个 PDF
B6 我的笔记Obsidian 式目录树（科目/时间两种整理）、★、备注、回收站 30 天、导出 Word/PPT/HTML/Markdown、附件多格式笔记树 + 导出下拉
B7 笔记模式全片最亮的一页：勾选回答 →「存为笔记」→ agent 整理成一份（去重、按主题重组、不照抄）→ 自动落库 + 可撤回；页边偏好面板往输入框插高亮要求；按教材章生成；@ 引用笔记；agent 直接管理笔记库全套走一遍
B8 学习反馈最近进展（只讲证据变化）、学习时间线、科目占比、活动趋势、笔记产出；每张图配数据表；明写"不是能力评分"；观察可当场纠正反馈页 + 点一次「纠正记录」

B7 值得单独讲透的三点

  • 自动存但可撤回——系统代你落库，事后给你一条「已存到 … ›《标题》」+ 撤回按钮。
  • agent 能直接操作你的笔记库——学生说「把散在科目根的笔记整理到第 3 章」，agent 就真的做了，并逐条回报「完成 N 项，M 项没做成」。
  • 它不许乱来——只能动本人的笔记；模型编造的 ID 会被丢掉并如实回报；agent 没有"彻底删除"这个能力，只能移进回收站。

B8 的讲法（对抗"你们是不是在给学生打分"）

「这一页里没有一个数字叫'掌握度'。我们只展示证据和观察的变化：哪条判断出现了相反证据、哪条观察被更正了。活动量（多少轮对话、多少份笔记）单独标注，并写明活动量不代表掌握程度。学生本人可以当场纠正任何一条观察。」

C · 课程建设端

必须 · 2 页
页讲什么
C1 建设台打开题目 → 结构化编辑（正文、关联知识点、多种参考解法、教学要点 hint_ladder、常见错误）→ 填审校说明 → 教师确认发布新版本；TA 账号此按钮禁用（现场演示权限差异）
C2 版本与回滚「贡献候选与版本记录」：待审核 / 待编辑 / 已发布 / 未采纳；eligible 候选可「打开编辑草稿」并自动挂上 rights 四项开关（runtime/rag/eval/training）；已发布的可「创建回滚版本」（需填回滚理由）

C2 要强调：这是"课程资产是可被审校、可被回滚的"，不是聊天记录攒出来的。

D · 教师 / TA 端

必须 · 4 页
页讲什么
D1 教学总览进行中作业 / 已提交 / 待批改 三个数字 + 待批改列表
D2 作业管理布置作业（课程/班级/人数/要求/资料保留时长/确认到期清理）；作业码；加助教；结束作业；删除作业资料（汇总报告保留）
D3 作品批改「辅助批改」生成候选建议 → TA 先确认/忽略 → 教师再「纳入报告」。这是"师-生-机"最直接的画面
D4 教学报告学习参与 / 作品提交 / 独立表现 / 确认问题 四个指标 + 已确认问题 + 教学建议 + 导出报告

「AI 只负责发现候选问题、聚合模式、减少机械工作；数学判断权始终在 TA 和教师手里。教师端输出的不是'AI 批改了多少份'，而是'本周值得教学关注的现象'。」

E · 五门课与学科 Harness

必须 · 2 页

这是技术实施质量维度最硬的一页。不要写"我们支持五门课"，把代码里真实注册的 harness 打出来：

课程学科 Harness（代码里真实注册的）
数学分析
旗舰 · 深做		定理条件 theorem_conditions · 量词边界 quantifier_boundary · 证明逻辑 proof_logic · 提示泄露 answer_leakage
常微分方程符号残差 symbolic_residual · 初边值条件 initial_boundary_conditions · 存在唯一性 existence_uniqueness · 数值交叉核对 numerical_crosscheck
大学物理单位量纲 unit_dimension · 模型假设 model_assumptions · 方向与符号 direction_sign · 数量级 magnitude_check
点集拓扑定义与约定 definition_convention · 量词逻辑 quantifier_logic · 反例核对 counterexample_check · 条件替换 condition_substitution
高等代数与解析几何符号矩阵核对 symbolic_matrix_check · 秩与维数条件 rank_dimension_conditions · 充要性 necessity_sufficiency

配一句原文解释 Harness 是干嘛的——注意措辞，别说"保证 100% 正确"：

「Harness 的目标是让 Course Mirror 更容易发现自己没有足够依据，并在必要时重试、降级回答或明确表达不确定性。」

每门课还有独立的课程教学策略，例如：

  • 数分：「明确量词顺序与变量依赖；使用定理前核对全部条件；证明必须区分直观与论证。」
  • 大物：「先说明物理模型和假设，再检查单位、方向与极限情形；不把数学运算代替物理解释。」
  • 心理学：「不从聊天做临床诊断或人格贴标签。」
潜台词这一页真正要证明的是：换一门课不是换一个 prompt。

F · 数据权利与隐私

必须 · 3 页
页要点
F1 六个授权字段每个数据源分别声明 allowed_for_runtime / allowed_for_rag / allowed_for_eval / allowed_for_training / retention_policy / license_note。检索与运行时双门控，代码里逐块过滤
F2 三条不能越的线① 私人对话与笔记默认本人可见，不因关联课程就向教师公开；② 不把"求助多"解释为"能力差"，不把"看答案"作为惩罚性指标；③ 教师端不做"谁问 AI 最多"这类监控面板
F3 生命周期学生模型随学生生命周期结束而删除；班级临时上下文随作业周期清理；只有去身份化、聚合、人工审核过的经验才进课程长期资产

「'学生上传用于当前答疑'不自动等于'允许训练'；'购买教材'不自动等于'允许批量复制或模型训练'。」

「信任一旦破坏，最珍贵的数据就会变成表演数据。」

G · 工程质量

加分 · 2 页

评委里一定有懂工程的人，这两页专门给他们。

页要点
G1 测试与验收后端 409 项自动化测试通过；22 个浏览器端到端验收脚本（覆盖对话、摘录、笔记、反馈、教材库、课表、首页登录等）；每次改动跑全量回归
G2 诚实边界下面这些是"我们做不到、所以如实说出来"的地方——这一页非常加分

G2 具体列这几条（都是代码里真实存在的行为）

  • 一整章教材（300+ 块 / 5–14 万字符）塞不进模型上下文。做法是：完整章节目录必发 + 按预算节选正文 + 如实写出"本章还有 N 块未列出"，并要求模型在材料没覆盖的地方标注「（超出所给材料，待核对）」。
  • 导出的 Word/PPT 是单向导出，不保证与网页逐像素一致；公式导出为纯文本。
  • 扫描件抽不出文字时直接说读不到，不假装读过。
  • 上传的文档超出额度时，回答里会说明"只看到文件名"。
  • 「学镜不替你做作业」：习题只给思路与框架，不代写整份。

H · 收尾

必须 · 1 页

十条共同原则里留这四条（最有辨识度的）：

  1. 先帮助学生，再观察学生。
  2. 诊断是学习的副产品，不是额外负担。（全程不用填任何问卷）
  3. 一次行为不能定义一个学生。
  4. 个性化必须真正改变下一次帮助，而不只是改变展示文案。

3演示视频分镜脚本

约 7 分钟，13 个镜头。叙事骨架直接采用产品文档里的"最终场景"——那本来就是写的验收画面：

「周三晚上，学生小王做数分作业，在一道 ε-δ 证明上卡住。他拍题、自己先想，然后点'我卡住了'。系统结合他的历史（曾在构造辅助对象时卡住过两次）只给第一级提示，而不是答案。他做出来后，系统记下一条学习证据——全程不用填任何问卷。

同一时间，TA 收到 AI 的批改辅助……教师据此决定下周一花十分钟讲这个问题。

学生的私人对话内容，教师全程看不到。」

拍摄手法

  • 跟着鼠标走，不要拍人。全程屏幕录制 + 旁白，不出现真人。
  • 每个镜头前 2 秒先定格再动鼠标，观众才看得清界面。
  • 鼠标移动要慢，必要时后期 1.2–1.5× 减速。
  • 关键界面加 3 秒放大镜（3–5 处即可）：提示标签「提示 1/3」、撤回按钮、操作回执、纠正记录表单、"不是能力评分"那行小字。
  • 切换端时给明显过渡（左侧栏高亮），否则观众分不清现在是学生还是教师视角。
  • 结尾定格 3 秒，留 Logo + 一句话总结。

4拍摄前必须做的准备

这一节最容易翻车。逐条做完再开机。

缺口一 本地库里没有任何教师/TA 账号，而且注册不了。
实测：data/browser-test.sqlite 里 35 个账号全是 student，而 .env 里 MIRROR_STAFF_INVITE_CODE= 是空的——教师/TA 注册需要邀请码，空值直接 403。
解决：在 .env 补一行 MIRROR_STAFF_INVITE_CODE=demo-team-invite，重启 API，再用这个邀请码注册一个教师账号。
缺口二 作业空间、作品提交、课程修订全是 0 条。
实测：sandbox_policies = 0、assignment_submissions = 0、course_revisions = 0。
也就是教师端和课程建设端现在拍出来全是空态。

按这个顺序预置一遍（约 15 分钟）

  1. 教师账号登录 → 作业管理 → 布置作业（课程 = 数学分析，名称「数列极限 · 第一次习题」，班级人数 32，记下作业码）
  2. 换学生账号（用你已有的 milkdragon）→ 我的作业 → 输作业码加入 → 提交作业（作答内容填一段真实的 ε-δ 作答，勾选"提交给教师"）
  3. 想演示"多人共性"的话，再注册 2–3 个学生账号各提交一份（批改页的学生列表才有内容）
  4. 教师端 → 作品批改 → 点「辅助批改」→ 保存一次批改 → 点「汇总问题」
  5. 教师端 → 课程建设 → 打开一道已有题目 → 改一处 → 填审校说明 → 发布一次（这样"版本记录"里才有东西）
验收教师端三个页面（总览 / 批改 / 报告）打开都不是空态；课程建设端「贡献候选与版本记录」至少有一条记录。

学生端数据也要喂一遍

现有演示账号只有 7 段对话、2 篇笔记，反馈页的图表会很空。至少要补：

  • 8–12 篇笔记，分布在 2–3 个科目、不同目录，其中 2–3 篇标 ★
  • 至少 3 个科目的对话（这样"各科目学习占比"才有分段）
  • 几条学习观察：在对话末尾的「补充学习反馈」里点几次「仍有困难 / 这次独立完成」
  • 想演示"观察被更正"的话，在反馈页对一条观察点一次「纠正记录」

5绝不能说错的话

左边是不该说的，右边是替换说法。这几处踩中任何一条，都会直接伤到创新性或可信度评分。

别这么说「我们训练 / 微调了大模型」
这么说「我们不训练大模型：通用基座 + 自建课程语料检索 + 智能体工作流 + 评测题质检。教材授权的训练权限本来就是关闭的。」
别这么说「AI 能保证答案正确」
这么说「Harness 让 Course Mirror 更容易发现自己没有足够依据，必要时降级或明确表达不确定性。我们不宣称 100% 正确。」
别这么说「系统会给学生做能力评估」
这么说「我们不做能力评分。只记录证据和观察，而且允许学生质疑和纠正。」
别这么说「老师在后台能看到学生的全部 AI 对话」
这么说「默认不把完整私人对话暴露给教师。教师端看的是摘要、趋势和与教学相关的证据——这是设计上的边界，不是功能缺失。」
别这么说「求助多的学生能力差」
这么说「求助行为本身不是负面行为。我们不把'求助多'解释为'能力差'。」
别这么说「五门课都已经产品化完成」
这么说「1 门深做（数学分析全闭环）+ 4 门真实可用，用来证明架构可以从一门课扩展到多门课。」
别这么说「拾记 / 学迹是我们训练的五个模型」
这么说「这是课程内的五个逻辑角色（答疑 / 寻知 / 编题 / 拾记 / 学迹），各有工具和权限边界，不必各自微调一个模型。」
别这么说「已经完成了真实课堂验证」
这么说目前没有真实课堂 / 真实学生实验数据，不要宣称已完成教学效果验证。（进度文档的验收表明确写着"真机 / 教学质量 ⚠️ 未完成"）

评委可能追问的三个问题，准备这三句

追问怎么答
这跟直接问 ChatGPT 有什么区别？「ChatGPT 给你答案；学镜记得你怎么卡住的，并且下一次给的帮助不一样。而且我们的回答可以核对到教材页码，材料不够时会如实标注。」
你们的 RAG 会不会泄露教材版权？「教材数据的授权字段是逐条声明的，检索和运行时双门控，代码里逐块过滤。训练权限全部关闭，仓库和提交材料里不含教材原文。」
教师端会不会变成监控工具？「不会，而且我们在产品文档里把它写成了负面清单：不做'谁问 AI 最多''谁疑似偷懒'这类面板。教师拿到的是'本周值得教学关注的现象'。」
