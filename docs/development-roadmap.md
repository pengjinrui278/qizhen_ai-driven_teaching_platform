# 比赛版开发路线（完整框架）

## 总体原则

比赛版不是单一数分问答 Demo。最终展示必须同时包含：

1. Student Mirror：统一学生入口、长期学习证据与个性化闭环；
2. 五门 Course Mirror：数分旗舰，高代、大物、点拓、常微分同步可用；
3. Assignment Workspace：连接学生过程、作业作品、TA 校准和教师洞察；
4. 学生端、课程建设端、教师/TA 端三个完整角色界面；
5. 数据来源、Harness、Eval、隐私和生命周期治理。

## 阶段 0：协议、边界与工程骨架

- 模块化单体、五门课程注册表；
- Course Mirror / Evidence / Harness 协议；
- CoursePack 与版权字段；
- 三端信息架构；
- 本地依赖、测试、构建。

## 阶段 1：五门课程共同底座 + 数分首条深链路

共同开发：上传/OCR、模型网关、混合检索、CoursePack 版本、事件记录、统一响应渲染。

数分开发：选择一个代表章节，完成知识节点、题目、解法路径、Hint Ladder、证明 Harness 和 Eval。

四门扩展：每门确定教材 Profile、代表章节、20～30 道人工核验题和首个学科 Harness；从阶段 1 起持续加入，不能留到最后换 Prompt。

## 阶段 2：Student Mirror 完整学生端

- 课程选择与自动路由；
- 拍题、自由提问、第一提示、继续提示、完整思路、解答检查；
- Learning Evidence 时间线；
- 假设—支持证据—相反证据—更新；
- 学习状态概览和“为什么这么说”；
- 个性化决策记录及统一提示对照。

## 阶段 3：Course Mirror 课程建设端

- CoursePack 导入、解析、审核、发布和回滚；
- 定义/定理/公式/题目/解法/提示的结构化编辑；
- Harness 规则管理；
- Eval Case 管理、批量运行和版本对比；
- 五门课程健康度、缺口和失败案例。

## 阶段 4：Assignment Workspace 与教师/TA 端

- 班级、作业和题目关联；
- 学生作品导入与 AI 候选问题；
- TA 确认、否定、修改和聚类；
- 全覆盖作品证据与部分深度过程证据分开展示；
- 班级现象、数据限制和教学建议；
- 截止报告与 Workspace 清理。

## 阶段 5：五门课程达到统一展示门槛

每门课程必须具备：

- 明确 Course/Profile；
- 可追溯课程资料；
- 结构化核心知识；
- 人工核验代表题；
- 渐进提示；
- 至少一个真正的学科 Harness；
- 统一 Learning Evidence；
- 独立 Eval；
- Student Mirror 统一调用。

数分在此基础上额外完成全闭环、更多章节、证明检查和真实学生实验。

## 阶段 6：治理、实验、推广方案与比赛呈现

- 学生告知、授权、查看、纠正、导出和删除；
- 教师数据可见边界；
- 模型、Prompt、CoursePack、Harness、Eval 版本绑定；
- 错误率、提示有效性、个性化收益、TA 确认率；
- 面向其他课程的 Course Mirror 创建手册；
- 面向学校平台的 SSO/API/LTI 集成适配方案，但比赛阶段不依赖学校授权。
